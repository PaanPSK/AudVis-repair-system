# AudVis Repair System
### ระบบแจ้งซ่อมอุปกรณ์โสตทัศนศึกษา

เว็บแอปพลิเคชันต้นแบบสำหรับบริหารจัดการงานแจ้งซ่อมอุปกรณ์โสตทัศนศึกษา พัฒนาขึ้นจากแนวคิดในการนำเทคโนโลยีดิจิทัลมาช่วยอำนวยความสะดวกให้แก่ครูและบุคลากรในโรงเรียนมัธยมที่เคยศึกษา โดยมุ่งเน้นการจัดการข้อมูลการแจ้งซ่อม การติดตามสถานะ และการตรวจสอบประวัติการซ่อมอุปกรณ์ให้เป็นระบบและสะดวกยิ่งขึ้น

โครงการนี้เป็นผลงานต้นแบบที่พัฒนาขึ้นเพื่อแสดงแนวทางการประยุกต์ใช้เทคโนโลยีกับงานสนับสนุนด้านโสตทัศนศึกษา โดยยังไม่ได้ส่งมอบหรือเปิดใช้งานเป็นระบบจริงในสถานศึกษา

## 🎯 วัตถุประสงค์ของโครงการ

1. เพื่อพัฒนาต้นแบบระบบแจ้งซ่อมอุปกรณ์โสตทัศนศึกษาผ่านเว็บไซต์
2. เพื่อให้สามารถรวบรวมและจัดเก็บข้อมูลการแจ้งซ่อมในรูปแบบฐานข้อมูล
3. เพื่อช่วยให้ผู้ดูแลระบบสามารถตรวจสอบและติดตามสถานะการดำเนินงานซ่อมได้อย่างเป็นระบบ
4. เพื่อเพิ่มความสะดวกในการค้นหาและตรวจสอบประวัติการซ่อมอุปกรณ์
5. เพื่อประยุกต์ใช้เทคโนโลยีเว็บแอปพลิเคชันในการพัฒนาระบบสนับสนุนการปฏิบัติงานในสถานศึกษา

## ✨ ความสามารถของระบบ (Features)

### สำหรับผู้แจ้งซ่อม
- แจ้งซ่อมอุปกรณ์โสตทัศนศึกษาผ่านเว็บไซต์
- ระบุชื่อผู้แจ้ง ห้องหรือสถานที่ อุปกรณ์ รายละเอียดปัญหา และระดับความเร่งด่วน
- ระบุหมายเลขครุภัณฑ์และอีเมลสำหรับรับการแจ้งผล
- สร้างหมายเลขรายการแจ้งซ่อมโดยอัตโนมัติในรูปแบบ `SR-YYYYMMDD-###`
- ตรวจสอบรายการแจ้งซ่อมและติดตามสถานะการดำเนินงาน
- ค้นหารายการแจ้งซ่อมจากหมายเลขรายการ ชื่อผู้แจ้ง หรือชื่ออุปกรณ์
- ตรวจสอบประวัติการซ่อมย้อนหลังด้วยหมายเลขครุภัณฑ์

### สำหรับผู้ดูแลระบบ
- เข้าสู่ระบบผู้ดูแลผ่าน Google Sign-In
- ตรวจสอบสิทธิ์ผู้ดูแลระบบด้วย Google ID Token
- ดูรายการแจ้งซ่อมที่บันทึกไว้ในระบบ
- ปรับปรุงสถานะการดำเนินงานซ่อม ได้แก่
  - รอดำเนินการ
  - กำลังซ่อม
  - ซ่อมเสร็จแล้ว
- ส่งอีเมลแจ้งผู้ดูแลเมื่อมีรายการแจ้งซ่อมใหม่
- ส่งอีเมลแจ้งผู้ร้องขอเมื่อรายการแจ้งซ่อมมีสถานะซ่อมเสร็จแล้ว

## 🏗️ โครงสร้างการทำงานของระบบ (System Architecture)

ระบบแบ่งการทำงานออกเป็น 3 ส่วนหลัก ได้แก่

1. **Frontend:** เว็บไซต์สำหรับรับข้อมูลแจ้งซ่อม แสดงรายการ และให้ผู้ดูแลจัดการสถานะ พัฒนาด้วย HTML, CSS และ JavaScript และเผยแพร่ผ่าน GitHub Pages
2. **Backend:** ใช้ Google Apps Script ทำหน้าที่ประมวลผลคำขอ ตรวจสอบสิทธิ์ และเชื่อมต่อกับฐานข้อมูลผ่าน Web App API
3. **Database:** ใช้ Google Sheets สำหรับจัดเก็บข้อมูลรายการแจ้งซ่อมและสถานะการดำเนินงาน

## 🔄 ขั้นตอนการทำงาน (Workflow)

1. ผู้ใช้งานเข้าสู่เว็บไซต์และกรอกแบบฟอร์มแจ้งซ่อม
2. Frontend ส่งข้อมูลไปยัง Google Apps Script Web App
3. Backend ตรวจสอบและบันทึกข้อมูลลง Google Sheets
4. ระบบสร้างหมายเลขรายการแจ้งซ่อมและแจ้งเตือนผู้ดูแลผ่านอีเมล
5. ผู้ดูแลเข้าสู่ระบบด้วยบัญชี Google ที่ได้รับอนุญาต
6. ผู้ดูแลตรวจสอบรายการและปรับปรุงสถานะการซ่อม
7. เมื่อสถานะเปลี่ยนเป็นซ่อมเสร็จแล้ว ระบบจะส่งอีเมลแจ้งผู้ร้องขอ

## 🔐 การตรวจสอบสิทธิ์และความปลอดภัย (Security)

- ใช้ Google Identity Services สำหรับการเข้าสู่ระบบผู้ดูแล
- ตรวจสอบ Google ID Token ก่อนอนุญาตให้ดำเนินการในส่วนของผู้ดูแลระบบ
- กำหนดบัญชีอีเมลที่มีสิทธิ์เข้าถึงฟังก์ชันสำหรับผู้ดูแลผ่านการตั้งค่าฝั่ง Backend
- แยกส่วน Frontend และ Backend ออกจากกัน โดยเก็บโค้ดฝั่ง Google Apps Script และข้อมูลการตั้งค่าที่สำคัญไว้ในระบบส่วนตัว ไม่เผยแพร่ไว้ใน Public Repository

**ข้อจำกัดด้านความปลอดภัย:** ในต้นแบบนี้มีการตรวจสอบ ID Token ผ่าน Google Token Info Endpoint (`tokeninfo`) ซึ่งเหมาะสำหรับการทดสอบและพัฒนาต้นแบบ แต่ยังไม่ใช่แนวทางตรวจสอบ Token ที่เหมาะสมสำหรับระบบ Production ที่ต้องการความปลอดภัยสูง จึงควรพัฒนากลไกการตรวจสอบลายเซ็นและข้อกำหนดของ Token ให้รัดกุมยิ่งขึ้นก่อนนำไปใช้งานจริง

## 📌 ขอบเขตและสถานะของโครงการ (Project Scope)

โครงการนี้พัฒนาขึ้นในรูปแบบ Web Application Prototype โดยครอบคลุมการแจ้งซ่อม การจัดเก็บข้อมูล การค้นหารายการ การตรวจสอบประวัติการซ่อม การจัดการสถานะโดยผู้ดูแล และการแจ้งเตือนผ่านอีเมล

ระบบมีการเผยแพร่ส่วน Frontend และเชื่อมต่อกับ Backend เพื่อทดสอบการทำงานแล้ว อย่างไรก็ตาม ยังไม่ได้ส่งมอบหรือเปิดใช้งานเป็นระบบจริงในสถานศึกษา และยังสามารถพัฒนาต่อยอดในด้านความปลอดภัย การจัดการสิทธิ์ และการปรับให้เหมาะสมกับการใช้งานจริงได้ในอนาคต
